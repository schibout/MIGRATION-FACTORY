Chargement des articles SAP

Charger le référentiel article depuis les tables SAP extraites (raw_data) vers les tables cibles IFS (clean_data), vérifier le résultat et générer les fichiers d'export.

•

Vue d'ensemble

Le chargement des articles SAP est porté par le module « Données de base des Articles » (ordre d'exécution 8, domaine IFS_Articles). Il lit les tables SAP déjà extraites dans raw_data et alimente les tables IFS dans clean_data, dans un ordre imposé par les dépendances :

1alimenter_ifs_article()article maître consolidé
2alimenter_part_catalog()catalogue article (table de base)
3alimenter_inventory_part()article magasin par site
4alimenter_inventory_part_planning()données de planification
5alimenter_purchase_part()article acheté
6alimenter_purchase_part_supplier()lien article – fournisseur
7alimenter_sales_part()article vendu

Les sources SAP utilisées :

Table raw_dataContenu SAP
article_definitifliste des articles retenus pour la migration (périmètre validé métier)
mara / maktfiche article générale et désignations
marcdonnées article par division (site)
mvkedonnées de vente
mbewvalorisation
marddonnées magasin
einafiches info-achat (liens fournisseurs)

Ordre de chargement. Le module Fournisseurs doit avoir été chargé avant les articles : purchase_part_supplier relie chaque article à son fournisseur renuméroté (600000+) via la correspondance supplier_legacy_sap_id. Sans fournisseurs chargés, les liens article–fournisseur sortent vides. Les articles PHL, eux, se chargent après les articles SAP (ils s'ajoutent au catalogue existant).

1

Vérifier les données SAP extraites

  1. Ouvrir le menu Données SAP › Articles pour contrôler visuellement les articles extraits (recherche par code, désignation, type).
  2. Vérifier que l'extraction SAP est récente : menu Extraction, onglet historique. Les tables mara, marc, mvke, mbew, mard et eina doivent avoir été extraites.
  3. Vérifier le périmètre : la table raw_data.article_definitif contient la liste des articles retenus. C'est elle qui délimite ce qui sera chargé.

Ne jamais modifier les tables raw_data directement : elles sont la copie fidèle de SAP. Toute correction se fait soit dans SAP puis ré-extraction, soit dans les règles de transformation.

2

Lancer le chargement

  1. Ouvrir le menu Chargement des données.
  2. Repérer la carte « Données de base des Articles » (domaine IFS_Articles).
  3. Cliquer sur Exécuter. Le module enchaîne les 7 fonctions du pipeline ; le journal d'exécution s'affiche en direct (messages PostgreSQL inclus : nombre de lignes insérées par table, durée de chaque étape).
  4. Attendre le statut Succès. En cas d'erreur, le journal indique la fonction en cause et le message PostgreSQL ; l'exécution s'arrête à la première erreur.

Rejouable sans risque. Le chargement est conçu pour être relancé : les tables sont rechargées ou complétées de façon idempotente. Relancer le module après une correction ne crée pas de doublons.

3

Vérifier le chargement

Contrôles visuels : menu Données IFS › Articles (contenu des tables cibles), ou requêtes de comptage :

SELECT
  (SELECT count(*) FROM clean_data.ifs_article_maitre)  AS article_maitre,
  (SELECT count(*) FROM clean_data.part_catalog)        AS part_catalog,
  (SELECT count(*) FROM clean_data.inventory_part)      AS inventory_part,
  (SELECT count(*) FROM clean_data.purchase_part)       AS purchase_part,
  (SELECT count(*) FROM clean_data.sales_part)          AS sales_part;

Règles de cohérence à connaître pour interpréter les écarts :

  • part_catalog est la table de base : toutes les tables filles (inventory, purchase, sales) ne contiennent que des articles présents dans le catalogue. Un article absent du catalogue n'apparaît nulle part ailleurs.
  • sales_part est volontairement plus petite : les types d'articles non vendus (NLAG, HIBE, ERSA…) sont exclus des articles de vente. Un écart entre part_catalog et sales_part est donc normal.
  • purchase_part_supplier : vérifier que les vendor_no sont bien des numéros renumérotés (600000+), pas les anciens numéros SAP.

Repérer les articles du périmètre qui n'ont pas été chargés :

SELECT a.*
FROM raw_data.article_definitif a
WHERE NOT EXISTS (
    SELECT 1 FROM clean_data.part_catalog pc
    WHERE pc.part_no = TRIM(a.matnr)
);
4

Exporter les articles

  1. Ouvrir le menu Export des données.
  2. Sélectionner la catégorie Article : chaque table cible IFS a sa requête d'export (part_catalog, inventory_part, purchase_part, sales_part, manuf_part_attribute…).
  3. Lancer l'export : un fichier ZIP contenant les CSV est généré, prêt à être transmis pour le chargement IFS.

Cache de 5 minutes. Les exports sont mis en cache : si vous relancez un export juste après un rechargement, attendez 5 minutes ou le fichier peut refléter l'état précédent.

5

Aller plus loin
